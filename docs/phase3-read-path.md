# Phase 3 read path

The public preview route uses CDN-compatible response headers, then Redis, then a PostgreSQL streaming replica. The local demo does not deploy a CDN. A replica connection error falls back to the primary. Redis timeouts are treated as misses. Redis stores only the validated public preview shape, never `html_full` or draft content. A short single-flight lock prevents multiple API instances from filling the same key at once; TTL jitter spreads expirations.

`POST /publications/:pubId/posts/:postId/unpublish` changes the post state and deletes its preview key. The API never serves unpublished posts from PostgreSQL. Existing CDN copies can remain for their 60-second `s-maxage`; a production unpublish requiring immediate removal needs a CDN purge integration. Redis invalidation can fail during an outage, in which case its TTL bounds stale content. A replica lag window can also briefly reintroduce the pre-unpublish preview after invalidation. This limitation must be considered before using this for sensitive takedowns.

`GET /public/:subdomain/posts/:slug/full` sends `private, no-store`. Free posts return their full body. Paid posts return 503 until Phase 4 implements reader identity and database-backed entitlements. This is intentional fail-closed behavior.

Compose configures PostgreSQL streaming replication from `postgres` to `postgres-replica`. The primary's initial database setup appends a replication entry to `pg_hba.conf`. Existing PostgreSQL data directories created before this change need that entry added manually and a replica base backup; the new named volumes only initialize on an empty deployment. Verify with `SELECT pg_is_in_recovery()` on port 5433 (must return true), and `SELECT pg_last_wal_replay_lsn()` on the replica after a write.

To measure the cached path, run `k6 run -e POST_PATH=/public/<subdomain>/posts/<slug> loadtests/read-path.js` against a seeded, running stack. For the uncached path, stop Redis and bypass the CDN, then run `k6 run -e MODE=uncached -e POST_PATH=/public/<subdomain>/posts/<slug> loadtests/read-path.js`. These are targets, not benchmark results. `k6` is not installed in the current local environment, so no throughput or p95 measurement has been recorded. The API exposes preview cache hit, miss and Redis error counters at `/metrics`. Do not record numbers until a real run has completed.
